## 1. 30 秒诊断

按顺序问四个问题：

1. `profile/self` 返回 0 吗？→ 不是 0 先解决登录，别改代码。
2. 失败的是列表还是写操作？→ 列表 403 基本是签名/参数；写操作 403 基本是多了或少了一个头。
3. 接口返回 `status_code:0` 但数据没变？→ 参数名/类型错了（`item_type_map` vs `aweme_type_map`、数字 vs 字符串）。
4. 清完还有残留？→ 还有别的子类型（音乐/合集/短剧/收藏夹）没清，或 `fatal_ids` 里的失效条目。

## 2. 错误对照表

| 现象 | 根因 | 处置 |
|---|---|---|
| `403 Blocked by ArgusSecurityPlugin Uifid Not Found` | 请求没带 `uifid` 参数/头 | 用页面内 `fetch`；或补 `uifid` |
| `403 ... Signature Not Found` | 缺 `x-secsdk-web-signature` | 只能页面内发，让 secsdk 签 |
| `403 ... Sign Invalid` | 签名过期/回放/别的会话 | 不要回放，重新在页面里发 |
| `403` 空 body | 头/参数组合异常（常见于取关加了 `x-secsdk-csrf-token`） | 减参数，只留 `Content-Type` + `uifid` |
| `status_code: 8` `用户未登录` | 会话被踢；或 query 带了别的会话的 `uid=` | 重新扫码；删掉 `uid=` |
| `status_code: 5` | 缺基础参数（`device_platform` 等） | 补齐第 10 节基础参数 |
| `404 Unsupported path(Janus)` | 路径/方法错 | 收藏列表是 POST 不是 GET；批量取消是 `.../cancel/collect/multi/` |
| `200` + `status_msg: "url doesn't match"` | 命中旧接口（如 `mix/collect`） | 换 `mix/cancel/collect/multi` |
| `status_code:0` 但 `fatal_ids` 一堆 | 类型映射错（图文没映射成 2） | `item_type_map[68] = 2` |
| 取消收藏后 `favoriting_count` 不变 | 计数缓存 | 忽略，用列表验收 |
| 列表返回 0 但页面还有内容 | `cursor=0` 空窗页 | 首次请求不带 cursor |
| 关注列表每页只多 1 个人 | `max_time` 含首条语义 | 改“删完重拉首页”策略 |
| `offset` 调了没反应 | 该接口忽略 offset | 不要用 offset |

## 3. 会话生命周期

```
扫码/短信登录
   └─ sessionid + ttwid + uifid + web_sign_token 落到浏览器
        └─ 页面内 fetch 自动签名（a_bogus / secsdk-signature / msToken）
             └─ 高频写操作
                  ├─ 正常：继续
                  ├─ 触发「身份验证」：让用户收短信，页面完成，会话保留
                  └─ 会话被踢：status_code 8 → 只能重新扫码
```

关键事实：

- **旧 cookie 注入救不回被踢的会话**。服务端已吊销，cookie 里还有 `sessionid` 也没用。
- **重新登录后 uifid/webid 会变**，抓到的旧请求头不能复用。
- **身份验证（短信）不是封号**，是风控挑战，用户手动完成即可。
- 一个会话里连续写上万条，被踢概率显著上升；分批、跨天做更安全。

## 4. 三个翻页陷阱（重点）

### 4.1 收藏：`cursor=0` 是空窗

`listcollection` 带 `cursor=0` 时返回的页可能只有 `disabled_item_ids`，`aweme_list` 为 `null`，`has_more` 却还是 1。
**症状**：脚本判断“没数据 → 清空了”，但网页上还有几百条。
**正解**：第一次请求**不带 `cursor`**，拿返回值再往下翻。

### 4.2 关注：`max_time` 含首条、`offset` 无效

`max_time=1792498542` 返回的是“时间 ≤ 1792498542”的最新 20 条，其中第一条就是上一页的第一条。
所以“原样回传 max_time”= 每页只前进 1 条；`offset=20/40` 完全被忽略。
**正解**：不按时间翻页。拉首页 → 把页内非互关全部取关 → 重新拉首页（列表已收缩）。整页都是互关时，把 `max_time` 设为响应值跳过最上面一个。

### 4.3 点赞：列表会因删除而整体前移

点赞首页 `max_cursor=0` 永远返回最新 50 条，删掉后下一批自动补位。
**正解**：边删边拉首页，不要先枚举 1 万条再删（既慢又会因游标漂移漏删）。
**判断卡住**：记录首页第一条 id，连续 3 次不变就停。

## 5. 数据一致性：别被计数骗了

- `favoriting_count` 可能延迟数分钟，甚至在你清空后仍显示旧值。
- 收藏列表里的 `disabled_item_ids` 是已失效作品，删不掉，也不该算“没清干净”。
- 文件夹的 `total_number` 可能是旧值；点进文件夹看真实内容。
- 验收一律用列表接口（见 SKILL.md 第 5 节），不要用页面数字。

## 6. 已被证明无效的方案

| 方案 | 结果 |
|---|---|
| Node/Python 直接请求 + 本地 `a_bogus` | 列表/写接口 403（缺 secsdk 签名） |
| 回放浏览器抓到的 `x-secsdk-web-signature` | `Sign Invalid`（绑定会话与时间） |
| 把旧会话 cookie 注入新浏览器 | 页面“未登录”或立刻弹验证 |
| 桌面端反编译 `main.dll` 找请求 | 成本极高；页面已能直接签，没必要 |
| 用 `mix/collect` 取消合集 | 返回 0 但 `url doesn't match`，没删 |

**桌面端 / CDP 备选**（网页登录彻底不可用时）：

1. 完全退出抖音桌面端（含 `douyin_guard`）。
2. `"D:\douyin\douyin.exe" --remote-debugging-port=9222` 启动。
3. `curl http://127.0.0.1:9222/json` 能看到页面，就 `agent-browser connect http://127.0.0.1:9222`，之后同样在页面里 `fetch`。
4. 注意：桌面端可能单实例锁/守护进程拉起，需要先杀掉 `douyin_guard`。

## 7. 风控信号与止损

按严重程度：

1. 偶发 `429` / 返回空列表 → 降速，暂停 1~2 分钟。
2. 弹滑块验证码 → 立即停脚本，人工完成。
3. 重新登录要求「身份验证」短信 → 当天停止批量操作。
4. `status_code:8` 会话被踢 → 当天停止；隔 24h 再试。
5. 功能被限制（不能点赞/关注）→ 停止一切自动化，等限制解除。

节奏建议：点赞 50/批、收藏 20/批、取关 1 条/请求；间隔 250~600ms；每 50 条停 2.5s；单次会话 ≤ 2000 条。

## 8. 账号安全

- cookie / uifid / webid 等同登录态，**不要写进仓库、issue、聊天记录**；`.env` 必须 `.gitignore`。
- 操作完成后建议改密或在「登录设备管理」里踢掉自动化设备。
- 只操作自己的账号，且获得明确授权；批量取消不可撤销。
